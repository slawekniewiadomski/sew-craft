- Q1 — coalesce autosave rows: keep the newest autosave row, never prune manual
  rows. This reverses the predecessor spec's "no pruning" promise and is recorded
  in `docs/architecture/data-model.md`.
- Q2 — 1.5 s idle debounce, 10 s maximum wait.
- Q3 — the first committed change on a never-saved project autosaves.
- Q4 — an autosave `409` pauses the save bar; the Reload/Overwrite dialog opens
  only on an explicit Save.
- Q5 — transient failures retry after 2/4/8/16 s, capped at 30 s.
- Q6 — best-effort `keepalive` flush on tab hide/unload within the browser
  budget.
- Q7 — never autosave while read-only or while an upgrade is pending.

## Non-goals

- A second persistence model, draft endpoint or offline queue.
- Restoring, diffing or listing checkpoints from the UI.
- Changing the document schema, commands or the geometry package.
- Retry/backoff on the manual Save button.
- Multi-tab live sync (a stale autosave still pauses on `409`).

## Assumptions

- The editor has one writer: `EditorView.persist`.
- `expected_version` remains the conflict token; `markSaved` records the exact
  snapshot sent, so edits during a write stay dirty.
- Docker (Pest) and npm (Vitest) are the validation entry points.
